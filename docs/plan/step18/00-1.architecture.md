## 컴포넌트 다이어그램

### 신규 컴포넌트: activity-logger.js

```
src/utils/activity-logger.js
├── createActivityLogger(config)   → logger 인스턴스 생성
├── logger.auth(event, details)    → [AUTH] 카테고리 로그
├── logger.doc(event, details)     → [DOC] 카테고리 로그
├── logger.mcp(event, details)     → [MCP] 카테고리 로그
└── logger.admin(event, details)   → [ADMIN] 카테고리 로그
```

**설계 원칙:**
- 기존 `src/utils/logger.js`를 **내부적으로 사용** (새 로거 생성 안 함)
- 카테고리별 함수만 래핑하여 일관된 로그 포맷 보장
- 별도 미들웨어 불필요 — 각 라우트/컨트롤러에서 직접 호출

### 변경 컴포넌트: config-loader.js

```
config.auth 확장:
  ├── signupMode: "approval" | "self"     (신규, 기본값: "approval")
  └── selfSignup:                          (신규)
      └── defaultGroupName: "Viewer"       (기본값: "Viewer")
```

### 변경 컴포넌트: auth-controller.js → signup()

```
signup(req, res)
  ├── 공통: 이메일 검증, 도메인 검사, 패스워드 검증, 중복 검사
  ├── if signupMode === "self":
  │   ├── userStore.create() — 즉시 사용자 생성
  │   ├── sessionService.createSessionForUser() — 세션 생성
  │   ├── activityLogger.auth('SIGNUP_SELF', ...) — 로그
  │   └── 응답: { success, mode: "self", session }
  └── else (approval):
      └── 기존 로직 유지 (pending_verification → ...)
```

```json5
// 기존 필드 (변경 없음)
auth: {
  requireReadLogin: false,
  sessionTimeout: 3600000,
  allowSignup: true,
```
