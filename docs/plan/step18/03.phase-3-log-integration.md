# Phase 3: 활동 로그 전체 통합

## 목적

Phase 1에서 생성한 `activity-logger.js`를 전 라우트에 적용하여 인증, 문서, MCP, 관리 이벤트를 로그 파일에 기록.

## 선행 조건

- Phase 1 완료 (activity-logger 모듈 사용 가능)
- Phase 2와 독립적 (병렬 실행 가능)

## 구현 체크리스트

### 3.1 인증 이벤트 로그 (FR-18-005)

**파일**: `src/controllers/auth-controller.js`

**삽입 위치와 로그 호출**:

| 함수 | 위치 | 호출 |
|------|------|------|
| `login()` | 로그인 성공 응답 직전 | `activityLogger.auth('LOGIN', { email, ip })` |
| `login()` | 로그인 실패 시 | `activityLogger.authWarn('LOGIN_FAILED', { email, ip, reason })` |
| `logout()` | 세션 삭제 후 | `activityLogger.auth('LOGOUT', { email, ip })` |
| `signup()` | 승인 모드 가입 요청 시 | `activityLogger.auth('SIGNUP_REQUEST', { email, ip })` |

**파일**: `src/controllers/admin/admin-registration-controller.js`

| 함수 | 위치 | 호출 |
|------|------|------|
| 승인 처리 | 상태 approved로 변경 후 | `activityLogger.auth('SIGNUP_APPROVED', { email, by: adminEmail })` |
| 거부 처리 | 상태 rejected로 변경 후 | `activityLogger.auth('SIGNUP_REJECTED', { email, by: adminEmail })` |

**파일**: `src/services/session-service.js`

| 함수 | 위치 | 호출 |
|------|------|------|
| `validateSession()` | 세션 만료 삭제 시 | `activityLogger.auth('SESSION_EXPIRED', { email: session.email })` |

**주의**: session-service에서 activity-logger를 사용하려면 init 시 전달하거나, 만료 시점에 콜백 패턴 사용. 단순 구현: `validateSession()` 내부에서 만료 삭제 시 직접 호출.

### 3.2 문서 이벤트 로그 (FR-18-006)

**파일**: `src/routes/api.js`

각 엔드포인트 핸들러 내부, 성공 응답 직전에 삽입:

```javascript
const activityLogger = require('../utils/activity-logger');
```

| 엔드포인트 | 이벤트 | 로그 호출 |
|-----------|--------|----------|
| `GET /api/entry` (문서 읽기) | API_READ | `activityLogger.doc('API_READ', { path, user: extractUser(req), ip: extractIp(req) })` |
| `PUT /api/entry` (문서 생성/수정) | CREATE 또는 UPDATE | `activityLogger.doc(isNew ? 'CREATE' : 'UPDATE', { path, user, ip, size: body.length })` |
| `DELETE /api/entry` | DELETE | `activityLogger.doc('DELETE', { path, user, ip })` |
| `POST /api/upload` | UPLOAD | `activityLogger.doc('UPLOAD', { path, user, ip, size: file.size })` |
| `POST /api/mkdir` | MKDIR | `activityLogger.doc('MKDIR', { path, user, ip })` |

**파일**: 문서 뷰 라우트 (웹 렌더링)

| 엔드포인트 | 이벤트 | 로그 호출 |
|-----------|--------|----------|
| `GET /doc/*` (웹 열람) | VIEW | `activityLogger.doc('VIEW', { path, user, ip })` |

### 3.3 MCP 이벤트 로그 (FR-18-007)

**파일**: `src/routes/mcp.js`

**삽입 위치**: `tools/call` 처리 블록에서 도구 실행 전후에 삽입.

```javascript
// tools/call 핸들러 내부
const toolName = params.name;
const user = authResult ? authResult.user : null;
const userLabel = user?.email || (user?.name ? `apikey(${activityLogger.maskKey(user.name)})` : 'anonymous');

// 도구 실행 전 (또는 성공 후)
activityLogger.mcp('TOOL=' + toolName, {
  user: userLabel,
  ip: req.ip,
  args: summarizeArgs(params.arguments)  // 긴 인자는 요약
});

// 에러 시
activityLogger.mcpError('TOOL=' + toolName + ' ERROR', {
  user: userLabel,
  ip: req.ip,
  error: error.message
});
```

**인자 요약 함수** (mcp.js 내부 또는 activity-logger에 추가):

```javascript
function summarizeArgs(args) {
  if (!args) return '{}';
  const summary = {};
  for (const [k, v] of Object.entries(args)) {
    if (typeof v === 'string' && v.length > 100) {
      summary[k] = v.substring(0, 100) + '...[truncated]';
    } else {
      summary[k] = v;
    }
  }
  return JSON.stringify(summary);
}
```

**추가 MCP 이벤트**:

| 이벤트 | 위치 | 로그 호출 |
|--------|------|----------|
| 초기화 | `initialize` 메서드 처리 시 | `activityLogger.mcp('INITIALIZE', { ip })` |
| 인증 실패 | 인증 검사 실패 시 | `activityLogger.mcpError('AUTH_FAILED', { ip, tool: toolName })` |

## 보안 주의사항

- 패스워드는 절대 로그에 기록하지 않음
- API 키는 `maskKey()` 함수로 앞 8자만 표시
- 세션 토큰은 로그에 기록하지 않음
- 문서 내용(body)은 로그에 기록하지 않음 — 경로와 크기만 기록

## 테스트 시나리오

### 정상 케이스

**TC-3-01**: 로그인 성공 로그

- **Given**: 서버 실행 중, 유효한 사용자 존재
- **When**: `POST /api/auth/login { email: "user@co.com", password: "Pass1234" }` 성공
- **Then**: 로그 파일에 `[AUTH] LOGIN email=user@co.com ip=...` 기록

**TC-3-02**: 문서 열람 로그

- **Given**: 로그인한 사용자
- **When**: `GET /doc/guide/setup` 요청
- **Then**: 로그 파일에 `[DOC] VIEW path=/guide/setup user=user@co.com ip=...` 기록

**TC-3-03**: MCP 도구 호출 로그

- **Given**: API 키로 인증된 MCP 클라이언트
- **When**: `tools/call` → `read_document { path: "/docs/readme.md" }`
- **Then**: 로그 파일에 `[MCP] TOOL=read_document user=apikey(a1b2c3d4...) ip=... args={"path":"/docs/readme.md"}` 기록

### 예외 케이스

**TC-3-04**: 로그인 실패 로그

- **Given**: 존재하지 않는 이메일
- **When**: `POST /api/auth/login` 실패
- **Then**: 로그 파일에 `[AUTH] LOGIN_FAILED email=wrong@co.com ip=... reason=INVALID_CREDENTIALS` 기록

**TC-3-05**: MCP 인증 실패 로그

- **Given**: 잘못된 API 키
- **When**: MCP `tools/call` 요청
- **Then**: 로그 파일에 `[MCP] AUTH_FAILED ip=... tool=read_document` 기록

### 경계값

**TC-3-06**: MCP 인자가 매우 긴 경우

- **Given**: MCP `create_document` 호출, content 10000자
- **When**: 로그 기록
- **Then**: args 내 content가 100자로 truncated 표시
