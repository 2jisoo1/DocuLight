# Phase 2: 직접 가입 (Self-Registration) 구현

## 목적

`signupMode: "self"` 모드에서 사용자가 가입 폼 제출만으로 즉시 계정 생성 + 자동 로그인되는 흐름 구현.

## 선행 조건

- Phase 1 완료 (config-loader에서 `signupMode` 정규화, activity-logger 사용 가능)

## 구현 체크리스트

### 2.1 auth-controller.js — signup() 함수 모드 분기

**파일**: `src/controllers/auth-controller.js`

**변경 내용**: 기존 `signup()` 함수의 패스워드 해싱 이후, 기존 registration 로직 이전에 모드 분기 삽입.

```
signup(req, res) {
  // ... 기존 공통 검증 (이메일, 도메인, 패스워드, 중복) ...
  // ... 패스워드 bcrypt 해싱 ...

  const signupMode = settings.signupMode || 'approval';

  if (signupMode === 'self') {
    // ── 직접 가입 흐름 ──
    // 1. defaultGroupName으로 그룹 조회
    const defaultGroupName = settings.selfSignup?.defaultGroupName || 'Viewer';
    const group = groupStore.findByName(defaultGroupName);
    if (!group) {
      // 폴백: 'Viewer' 시스템 그룹
      const viewerGroup = groupStore.findByName('Viewer');
      if (!viewerGroup) {
        return res.status(500).json({ error: { code: 'GROUP_NOT_FOUND', message: 'Default group not found' } });
      }
      group = viewerGroup;
    }

    // 2. 사용자 즉시 생성
    const user = userStore.create({
      email: email,
      passwordHash: hashedPassword,
      groupId: group.id
    });

    // 3. 세션 생성
    const session = sessionService.createSessionForUser(
      user, group.permissions, settings
    );

    // 4. 쿠키 설정
    res.cookie('doclight_session', session.token, {
      httpOnly: true,
      sameSite: 'Strict',
      maxAge: settings.sessionTimeout
    });

    // 5. 활동 로그
    activityLogger.auth('SIGNUP_SELF', {
      email: email,
      ip: req.ip,
      group: group.name
    });

    // 6. 응답
    return res.json({
      success: true,
      mode: 'self',
      session: {
        permissions: session.permissions,
        expiresAt: session.expiresAt
      }
    });
  }

  // ── 승인 기반 흐름 (기존 코드 유지) ──
  // ... existing pending_verification → email → pending_approval ...
}
```

**주의사항**:
- `groupStore.findByName()` 메서드 존재 여부 확인 필요 → 없으면 `getAll().find(g => g.name === name)` 사용
- 기존 approval 흐름 코드는 **일절 수정하지 않음**
- `hashedPassword` 변수 이후에 분기 삽입

### 2.2 groupStore — findByName 확인/추가

**파일**: `src/stores/group-store.js`

**확인**: `findByName(name)` 메서드가 있는지 확인.

없으면 추가:
```javascript
function findByName(name) {
  const groups = getAll();
  return groups.find(g => g.name === name) || null;
}
```

exports에 추가.

### 2.3 signup.ejs — 모드별 UI 분기

**파일**: `src/views/signup.ejs`

**변경 내용**:

1. 서버에서 EJS로 `signupMode` 전달:
   ```javascript
   // auth-controller.js 또는 라우트에서
   res.render('signup', { signupMode: settings.signupMode || 'approval', ... });
   ```

2. signup.ejs 내 JavaScript에서 응답 처리 분기:
   ```javascript
   // 기존: approval 모드 메시지 표시
   // 변경: self 모드일 때 즉시 리다이렉트
   if (data.mode === 'self' && data.success) {
     window.location.href = basePath + '/';
     return;
   }
   // 기존 approval 모드 메시지 표시 유지
   ```

3. 가입 폼 안내 텍스트 모드별 분기:
   ```html
   <% if (signupMode === 'self') { %>
     <p class="signup-description">계정을 생성하면 즉시 사용할 수 있습니다.</p>
   <% } else { %>
     <p class="signup-description">가입 요청을 보내면 관리자 승인 후 사용할 수 있습니다.</p>
   <% } %>
   ```

4. 가입 폼 필드는 양 모드 동일: 이메일, 패스워드, 패스워드 확인

### 2.4 가입 페이지 라우트에 signupMode 전달

**파일**: signup 페이지를 렌더링하는 라우트 확인 후 수정.

`GET /signup` 핸들러에서:
```javascript
const authSettings = stores.authSettingsStore.get();
// allowSignup false → 리다이렉트
if (!authSettings.allowSignup) {
  return res.redirect(basePath + '/login?msg=signup_disabled');
}
res.render('signup', {
  basePath,
  signupMode: authSettings.signupMode || 'approval',
  // ... 기존 변수들
});
```

## 테스트 시나리오

### 정상 케이스

**TC-2-01**: 직접 가입 성공

- **Given**: `signupMode: "self"`, `allowSignup: true`
- **When**: `POST /api/auth/signup { email: "user@company.com", password: "Pass1234", passwordConfirm: "Pass1234" }`
- **Then**:
  - HTTP 200, `{ success: true, mode: "self", session: {...} }`
  - `data/users.json`에 사용자 추가됨
  - 세션 쿠키 설정됨
  - 사용자 그룹이 Viewer

**TC-2-02**: 승인 모드 기존 동작 유지

- **Given**: `signupMode: "approval"` (또는 미설정)
- **When**: `POST /api/auth/signup { email: "user@co.com", password: "Pass1234", passwordConfirm: "Pass1234" }`
- **Then**: 기존 동작 (pending_verification 또는 pending_approval)

### 예외 케이스

**TC-2-03**: 도메인 제한 위반 (직접 가입)

- **Given**: `signupMode: "self"`, `allowedEmailDomains: ["company.com"]`
- **When**: `POST /api/auth/signup { email: "user@other.com", ... }`
- **Then**: HTTP 400, `EMAIL_DOMAIN_NOT_ALLOWED`

**TC-2-04**: 이메일 중복 (직접 가입)

- **Given**: `signupMode: "self"`, 이미 `user@co.com` 존재
- **When**: `POST /api/auth/signup { email: "user@co.com", ... }`
- **Then**: HTTP 409, `EMAIL_ALREADY_EXISTS`

**TC-2-05**: defaultGroupName에 해당 그룹 없음

- **Given**: `selfSignup.defaultGroupName: "NonExistent"`
- **When**: 직접 가입 시도
- **Then**: Viewer 그룹으로 폴백, 정상 가입 완료

### 경계값

**TC-2-06**: 패스워드 정확히 8자

- **Given**: `signupMode: "self"`
- **When**: `password: "12345678"`, `passwordConfirm: "12345678"`
- **Then**: 가입 성공 (최소 길이 충족)
