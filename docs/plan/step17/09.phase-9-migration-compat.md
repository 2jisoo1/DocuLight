# Phase 9: 하위 호환성 + 마이그레이션

## 목표

기존 apiKey/apiKeys 기반 시스템에서 새 사용자 관리 시스템으로의 점진적 전환을 지원하고, CLI 패스워드 리셋 도구를 제공한다.

## 선행 조건

- Phase 8 완료 (보안 강화)

## 아키텍처 참조

- SRS NFR-17-009: 호환성
- SRS FR-17-012: CLI 패스워드 리셋
- SRS FR-17-013: 비밀번호 분실 안내

## 구현 체크리스트

### 9.1 config-loader.js 마이그레이션 로직

- [ ] 서버 시작 시 `apiKey`/`apiKeys` 필드 존재 확인
  - 존재하면 콘솔 경고: `[DEPRECATED] apiKey/apiKeys는 폐기 예정입니다. 사용자 관리 시스템을 사용하세요.`
- [ ] `validateApiKeys()` 호출 조건 변경:
  - 사용자 데이터(`users.json`)가 존재하면 → apiKeys 검증 스킵
  - 사용자 데이터 없으면 → 기존처럼 apiKeys 검증 (마이그레이션 전환기)
- [ ] `admin.sessionTimeout` 마이그레이션:
  - `auth-settings.json` 미존재 + `config.admin.sessionTimeout` 존재 시
  - 초기 `auth-settings.json` 생성 시 해당 값 이관
- [ ] 검증: 기존 config.json5 그대로 사용 시 서버 시작 + 경고 출력

### 9.2 Setup Wizard 마이그레이션 경로

- [ ] Setup Wizard에서 "기존 API Key로 마이그레이션" 옵션 추가 (선택적)
  - API Key 입력 필드 (기존 config의 apiKey와 일치 확인)
  - 일치하면 해당 키의 권한 정보로 슈퍼유저 생성
- [ ] apiKeys 배열의 `delete` 권한 → `write`로 자동 매핑
- [ ] 마이그레이션 완료 로그 기록
- [ ] 검증: 기존 API Key 입력 → 슈퍼유저 생성 성공

### 9.3 기존 폐기 엔드포인트 최종 정리

- [ ] Phase 3에서 추가한 폐기 안내 응답 확인:
  - `POST /api/admin/auth` → 410 + "POST /api/auth/login 을 사용하세요"
  - `POST /api/admin/logout` → 410 + "POST /api/auth/logout 을 사용하세요"
  - `GET /api/admin/session` → 410 + "GET /api/auth/session 을 사용하세요"
  - `POST /api/admin/session/refresh` → 410 + "POST /api/auth/session/refresh 를 사용하세요"
- [ ] 검증: 폐기 엔드포인트 호출 시 안내 메시지

### 9.4 CLI 패스워드 리셋 도구

- [ ] `scripts/reset-admin.js` 생성
- [ ] 사용법: `node scripts/reset-admin.js --email admin@example.com --password newPass123!`
- [ ] 처리:
  1. `config.json5`에서 `dataDir` 읽기
  2. `users.json`에서 이메일로 사용자 조회
  3. 슈퍼유저 그룹 소속 확인
  4. 새 패스워드 bcrypt 해시 생성
  5. 패스워드 업데이트 + 실패 카운터 리셋 + 잠금 해제
  6. 원자적 쓰기로 파일 저장
  7. 성공 메시지 출력
- [ ] 에러 처리:
  - `--email` 또는 `--password` 누락 → 사용법 출력
  - 사용자 미존재 → "사용자를 찾을 수 없습니다"
  - data 파일 없음 → "Setup이 완료되지 않았습니다"
  - 슈퍼유저 아님 → "이 도구는 슈퍼유저만 리셋할 수 있습니다"
- [ ] 보안: 서버 파일시스템 접근 가능한 관리자만 실행 가능
- [ ] 검증: 패스워드 리셋 후 새 패스워드로 로그인 성공

### 9.5 비밀번호 분실 안내 UI

- [ ] `login.ejs`에 "비밀번호를 잊으셨나요?" 링크 추가

  - 이메일 서버 설정의 `from` 주소 표시 (있는 경우)
  - 또는 "시스템 관리자에게 문의하세요" 일반 안내
- [ ] 검증: 링크 클릭 → 안내 텍스트 표시

### 9.6 config.example.json5 최종 업데이트

- [ ] `apiKey`, `apiKeys` 섹션에 `[DEPRECATED]` 주석 추가
- [ ] `dataDir`, `email` 설정 예시 추가
- [ ] `admin.sessionTimeout` → `auth-settings.json으로 이동` 주석
- [ ] 검증: 새 config.example.json5로 서버 시작 가능

## 테스트 시나리오

### 정상 케이스

**Given**: 기존 config.json5에 apiKey 설정 있고, users.json 없음
**When**: 서버 시작
**Then**: 경고 메시지 출력 + Setup Wizard 표시

**Given**: 유일한 슈퍼유저 패스워드 분실
**When**: `node scripts/reset-admin.js --email admin@test.com --password newPass!`
**Then**: 패스워드 변경 완료, 새 패스워드로 로그인 성공

### 예외 케이스

**Given**: users.json이 없는 상태
**When**: CLI 리셋 도구 실행
**Then**: "Setup이 완료되지 않았습니다" 에러

**Given**: Editor 사용자의 이메일로 CLI 리셋 시도
**When**: 실행
**Then**: "이 도구는 슈퍼유저만 리셋할 수 있습니다" 에러

### 경계값 테스트

**Given**: apiKeys 배열에 `permissions: ["read", "write", "delete"]`
**When**: 마이그레이션
**Then**: `delete` → `write` 매핑, 결과: `["read", "write"]`
