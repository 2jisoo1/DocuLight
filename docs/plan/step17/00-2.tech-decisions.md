# Step 17: 기술 결정 기록 (ADR)

## ADR-001: JSON 파일 기반 사용자 저장소

- **결정**: SQLite/DB 대신 JSON 파일을 사용자 데이터 저장소로 사용
- **근거**: SRS 제약 — "DB를 사용하지 않고 로컬 파일로 관리"
- **영향**: 1,000명 이하 규모에서만 적합. 전체 파일 로드/저장 방식이므로 대규모 시 성능 문제
- **완화**: 서비스 계층 분리로 향후 SQLite 전환 가능하게 설계

## ADR-002: bcrypt (cost factor 12)

- **결정**: 패스워드 해싱에 bcrypt 사용, cost factor 12
- **근거**: 업계 표준, Node.js `bcrypt` 패키지가 C++ 바인딩으로 성능 양호
- **대안**: scrypt, argon2 — 어느 것이든 충분하지만 bcrypt가 가장 널리 사용되고 검증됨
- **영향**: `npm install bcrypt`은 네이티브 빌드 필요. Alpine 등 일부 환경에서 빌드 이슈 가능
- **완화**: 빌드 실패 시 `bcryptjs` (순수 JS)로 대체 가능. 인터페이스 동일

## ADR-003: user-key SHA-256 해시 저장

- **결정**: user-key 원본을 저장하지 않고 SHA-256 해시만 저장
- **근거**: 데이터 파일 유출 시에도 API Key 노출 방지
- **영향**: 사용자에게 키를 생성/재발급 시 단 한 번만 보여줄 수 있음
- **인증 흐름**: 요청의 user-key → SHA-256 해싱 → in-memory `Map<hash, userId>` 조회

## ADR-004: 기존 세션 서비스 확장 (신규 생성 아님)

- **결정**: 기존 `session-service.js`를 확장하여 사용
- **근거**: 이미 in-memory Map 기반 세션, cleanup 타이머 등이 구현되어 있음
- **변경점**:
  - `createSession(apiKey, config)` → `createSession(user, authSettings)` 로 시그니처 변경
  - 세션 데이터에 `userId`, `email`, `groupId`, `permissions` 추가
  - `findApiKeyConfig()` 함수 제거 (폐기)
  - `invalidateByUserId(userId)` 함수 추가 (강제 로그아웃)

## ADR-005: 데이터 액세스 계층 분리 (stores/)

- **결정**: `src/stores/` 디렉토리에 JSON 파일 R/W 전용 모듈 배치
- **근거**: 서비스 계층과 파일 I/O를 분리하여 향후 저장소 교체 용이
- **패턴**: `base-json-store.js`에 공통 로직 (원자적 쓰기, 락, 백업)을 집중

## ADR-006: express-rate-limit (in-memory)

- **결정**: Rate Limiting에 `express-rate-limit` 패키지 사용 (in-memory 저장)
- **근거**: SRS 명시. 단일 프로세스 환경에서 in-memory가 가장 간단
- **영향**: 서버 재시작 시 Rate Limit 카운터 리셋됨
- **대안**: Redis 등 외부 저장소 — 현재 불필요 (단일 프로세스)

## ADR-007: nodemailer (SMTP)

- **결정**: 이메일 발송에 `nodemailer` 사용
- **근거**: Node.js SMTP 클라이언트 사실상 표준
- **영향**: config.json5에 SMTP 설정 추가. 미설정 시 가입 요청 기능 비활성화

## ADR-008: Setup Wizard를 미들웨어로 구현

- **결정**: Setup Guard를 전역 미들웨어로 구현
- **근거**: "사용자 0명이면 어떤 경로로든 Setup Wizard로 리다이렉트"라는 SRS 요구
- **위치**: `app.use()` 체인에서 가능한 앞쪽 (IP whitelist, request logger 바로 뒤)
- **제약**: `/setup` 자체와 Setup API 경로는 가드에서 제외

## ADR-009: auth-settings.json 분리 (config.json5 아님)

- **결정**: 인증 설정을 `data/auth-settings.json`에 별도 저장
- **근거**: 런타임에 /admin UI에서 변경 가능해야 함. config.json5는 정적 설정 파일이므로 런타임 쓰기에 부적합 (hot-reload와 충돌 위험)
- **영향**: 설정 로드 시 `auth-settings.json` > 기본값 우선순위

## ADR-010: 기존 apiKey/apiKeys 폐기 전략

- **결정**: 즉시 제거하지 않고 경고 메시지 출력 후 다음 메이저에서 제거
- **근거**: 기존 사용자의 점진적 전환 지원
- **마이그레이션 경로**: Setup Wizard에서 기존 API Key 검증 → 슈퍼유저 생성
- **코드 영향**: `config-loader.js`에서 `validateApiKeys()` 호출을 조건부로 변경 (사용자 데이터 존재 시 스킵)
