# Phase 2: 최초 설정 마법사 + 로그인/로그아웃

## 목표

사용자가 0명일 때 Setup Wizard를 표시하고, 이메일+패스워드 기반 로그인/로그아웃 기능을 구현한다.

## 선행 조건

- Phase 1 완료 (UserStore, GroupStore, AuthSettingsStore 사용 가능)

### 2.3 Setup API 엔드포인트

- [ ] `POST /api/auth/setup` 엔드포인트 구현
- [ ] 요청 body: `{ email, password, passwordConfirm }`
- [ ] 처리:
  1. `UserStore.getUserCount() > 0`이면 403 `SETUP_ALREADY_COMPLETE`
  2. 이메일 형식 검증
  3. 패스워드 강도 검증 (최소 8자)
  4. 패스워드 일치 검증
  5. `GroupStore.initialize()` — 기본 3개 그룹 생성
  6. `UserStore.create({ email, password, groupId: superuserGroupId })`
  7. `AuthSettingsStore.initialize()` — 기본 설정 생성
  8. Setup 완료 플래그 갱신
- [ ] 응답: `{ success: true }` → 클라이언트가 /login으로 리다이렉트
- [ ] 에러: 이메일 형식, 패스워드 강도, 일치 여부에 따른 400 응답
- [ ] 검증: Setup 완료 후 동일 API 재호출 시 403

### 2.6 로그인 API 엔드포인트

- [ ] `src/controllers/auth-controller.js` 생성
- [ ] `src/routes/auth-api.js` 생성 → `app.js`에서 `/api/auth` 마운트
- [ ] `POST /api/auth/login` 구현
  - `UserStore.findByEmail(email)`
  - 사용자 미존재 → 401 `INVALID_CREDENTIALS` (이메일/패스워드 구분 안 함)
  - `user.status === 'disabled'` → 401 `ACCOUNT_DISABLED`
  - `user.lockedUntil > Date.now()` → 429 `TOO_MANY_ATTEMPTS`

  - 성공: 실패 카운터 리셋 + 세션 생성 + 쿠키 설정 + 마지막 로그인 갱신

## 테스트 시나리오

### 정상 케이스

**Given**: 서버가 처음 시작됨 (data 비어있음)
**When**: 브라우저에서 `http://localhost:3000/` 접속
**Then**: `/setup` 페이지로 리다이렉트

**Given**: Setup 완료 후 슈퍼유저 존재
**When**: `/api/auth/login`에 올바른 이메일+패스워드 전송
**Then**: 세션 생성, 쿠키 설정, `{ success: true, session: {...} }` 응답

### 예외 케이스

**Given**: 슈퍼유저 존재 (Setup 완료)
**When**: `POST /api/auth/setup` 재호출
**Then**: 403 `SETUP_ALREADY_COMPLETE`

**Given**: 존재하지 않는 이메일로 로그인
**When**: `POST /api/auth/login` 전송
**Then**: 401 `INVALID_CREDENTIALS` (이메일 존재 여부 노출 안 함)

### 경계값 테스트

**Given**: 연속 5회 잘못된 패스워드로 로그인 시도
**When**: 6번째 로그인 시도
**Then**: 429 `TOO_MANY_ATTEMPTS` (올바른 패스워드여도 거부)
