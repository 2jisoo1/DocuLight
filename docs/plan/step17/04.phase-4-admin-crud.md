# Phase 4: 그룹/사용자 CRUD (Admin API + UI)

## 목표

슈퍼유저가 /admin에서 사용자와 그룹을 관리(생성/조회/수정/삭제)할 수 있는 API와 UI를 구현한다.

## 선행 조건

- Phase 3 완료 (인증 미들웨어 전환 완료)

## 아키텍처 참조

- [00-1.architecture.md](00-1.architecture.md): /admin 탭 구조 (권한별), 데이터 모델
- SRS FR-17-004: 그룹 관리 (CRUD)
- SRS FR-17-005: 사용자 관리 (CRUD)

## 구현 체크리스트

### 4.1 그룹 관리 API

- [ ] `src/controllers/admin/admin-group-controller.js` 생성
- [ ] `GET /api/admin/groups` — 그룹 목록 조회
  - 응답: `{ success: true, groups: [...] }` (각 그룹에 memberCount 포함)
- [ ] `POST /api/admin/groups` — 그룹 생성
  - body: `{ name, permissions }`
  - 권한 값 검증: `superuser`, `write`, `read`만 허용
  - 중복 이름 검사
- [ ] `PUT /api/admin/groups/:id` — 그룹 수정
  - body: `{ name?, permissions? }`
  - 시스템 그룹 권한 변경 불가
- [ ] `DELETE /api/admin/groups/:id` — 그룹 삭제
  - 시스템 그룹 삭제 불가
  - 소속 사용자 존재 시 삭제 불가
- [ ] `admin-api.js`에 라우트 등록 (슈퍼유저 전용: `requirePermission('superuser')`)
- [ ] 검증: CRUD 전체 + 보호 규칙

### 4.2 사용자 관리 API

- [ ] `src/controllers/admin/admin-user-controller.js` 생성
- [ ] `GET /api/admin/users` — 사용자 목록 조회
  - 응답: 이메일, 그룹명, 상태, 마지막 로그인 (패스워드 해시/키 해시 제외)
- [ ] `POST /api/admin/users` — 사용자 직접 추가
  - body: `{ email, password, groupId }`
  - 이메일 중복 검사, 그룹 존재 확인
  - user-key 자동 발급
  - 응답에 user-key 원본 포함 (이때만 반환)
- [ ] `PUT /api/admin/users/:id` — 사용자 수정
  - body: `{ groupId?, status? }`
  - 마지막 슈퍼유저 보호: 강등 불가, 비활성화 불가
  - 비활성화 시 해당 사용자의 모든 세션 즉시 삭제
- [ ] `DELETE /api/admin/users/:id` — 사용자 삭제
  - 자기 자신 삭제 불가
  - 마지막 슈퍼유저 삭제 불가
- [ ] `POST /api/admin/users/:id/reset-password` — 패스워드 리셋
  - body: `{ newPassword }`
  - bcrypt 해시 저장, 실패 카운터 리셋, 잠금 해제
- [ ] `POST /api/admin/users/:id/unlock` — 계정 잠금 해제
  - 실패 카운터 리셋, 잠금 해제
- [ ] `admin-api.js`에 라우트 등록 (슈퍼유저 전용)
- [ ] 검증: CRUD + 보호 규칙 + 세션 무효화

### 4.3 requirePermission 'superuser' 지원

- [ ] `admin-auth.js`의 `requirePermission()` 함수가 `'superuser'` 값도 처리하도록 확인
- [ ] 권한 계층: `superuser` ⊃ `write` ⊃ `read`
- [ ] 검증: superuser 권한 없는 사용자가 사용자 관리 API 접근 시 403

### 4.4 Admin UI — 사용자 관리 탭

- [ ] `public/js/admin.js`에 사용자 관리 탭 UI 추가
  - 사용자 목록 테이블 (이메일, 그룹, 상태, 마지막 로그인, 액션)
  - "사용자 추가" 버튼 → 모달 (이메일, 패스워드, 그룹 선택)
  - 사용자 추가 완료 시 user-key 표시 다이얼로그 ("이 키를 안전하게 보관하세요")
  - 사용자 편집 버튼 → 모달 (그룹 변경, 상태 변경)
  - 사용자 삭제 버튼 → 확인 다이얼로그
  - 패스워드 리셋 버튼 → 새 패스워드 입력 모달
  - 잠금 해제 버튼 (잠긴 사용자에만 표시)
- [ ] 권한에 따른 탭 가시성:
  - `superuser`: 모든 탭
  - `write`: 파일 관리 + 내 정보만
  - `read`: 내 정보만
- [ ] 검증: 사용자 추가/편집/삭제/리셋/잠금해제 UI 동작

### 4.5 Admin UI — 그룹 관리 탭

- [ ] `public/js/admin.js`에 그룹 관리 탭 UI 추가
  - 그룹 목록 테이블 (이름, 권한, 소속 사용자 수, 시스템 여부, 액션)
  - "그룹 추가" 버튼 → 모달 (이름, 권한 체크박스)
  - 그룹 편집 버튼 → 모달 (시스템 그룹은 이름만 수정)
  - 그룹 삭제 버튼 (시스템 그룹 비활성화, 사용자 존재 시 경고)
- [ ] 검증: 그룹 CRUD UI 동작

### 4.6 Admin UI CSS

  - 사용자/그룹 관리 테이블 스타일
  - 모달 다이얼로그 스타일

## 테스트 시나리오

### 정상 케이스

**Given**: 슈퍼유저로 /admin 로그인 상태
**When**: "사용자 추가" → 이메일, 패스워드, Editor 그룹 선택 → 생성
**Then**: 사용자 생성 완료, user-key 표시, 목록에 추가됨

**Given**: 슈퍼유저로 로그인, 2명의 슈퍼유저 존재
**When**: 다른 슈퍼유저를 Editor로 그룹 변경
**Then**: 변경 성공

### 예외 케이스

**Given**: 슈퍼유저 1명만 존재
**When**: 해당 슈퍼유저의 그룹을 Editor로 변경 시도
**Then**: 403 `LAST_SUPERUSER_PROTECTED`

**Given**: Editor 그룹에 사용자 2명 소속
**When**: Editor 그룹 삭제 시도
**Then**: 409 `GROUP_HAS_MEMBERS`

### 경계값 테스트

**Given**: 자기 자신 (현재 로그인한 슈퍼유저)
**When**: 삭제 버튼 클릭
**Then**: 403 `CANNOT_DELETE_SELF`
