# Phase 7: 이메일 서비스 + 가입 요청 워크플로우

## 목표

이메일 발송 서비스를 구현하고, 사용자 가입 요청 → 이메일 인증 → 슈퍼유저 승인/거절 워크플로우를 완성한다.

## 선행 조건

- Phase 5 완료 (인증 설정에서 allowSignup, allowedEmailDomains 관리 가능)
- Phase 6 완료 (내 정보 페이지)

## 아키텍처 참조

- SRS FR-17-007: 가입 요청 워크플로우
- SRS FR-17-008: 이메일 발송 서비스
- SRS FR-17-011: 가입 요청 UI

### 7.2 이메일 서비스

- [ ] `src/services/email-service.js` 생성
- [ ] `initialize(emailConfig)`: nodemailer transporter 생성
- [ ] `isConfigured()`: 이메일 설정 유무 반환
- [ ] `sendVerificationEmail(email, token, baseUrl)`: 가입 인증 이메일 발송
  - 인증 링크: `{baseUrl}/verify/{token}`
  - 24시간 유효 안내
- [ ] `sendApprovalEmail(email, loginUrl)`: 가입 승인 알림 이메일
- [ ] `sendRejectionEmail(email)`: 가입 거절 알림 이메일
- [ ] `verify()`: SMTP 연결 테스트
- [ ] 에러 처리: 발송 실패 시 1회 재시도, 재시도도 실패 시 로그 기록
- [ ] 검증: SMTP 연결 + 이메일 발송 동작

### 7.3 가입 요청 API

- [ ] `auth-controller.js`에 추가
- [ ] `POST /api/auth/signup` — 가입 요청
  - body: `{ email, password, passwordConfirm, message }`
  - 처리:
    1. `AuthSettingsStore.get().allowSignup` 확인 → false면 403
    2. 이메일 형식 검증
    3. 이메일 도메인 검증 (allowedEmailDomains)
    4. 기존 사용자 이메일 중복 확인 → 409 `EMAIL_ALREADY_REGISTERED`
    5. 대기 중 이메일 중복 확인 (pending_verification/pending_approval) → 409 `EMAIL_ALREADY_PENDING`
    6. 거절된 요청은 동일 이메일 재요청 가능
    7. 만료된 요청도 동일 이메일 재요청 가능 (기존 레코드 expired 처리)
    8. bcrypt 해시 + 인증 토큰 생성
    9. `RegistrationStore.create(...)` (status: pending_verification)
    10. 인증 이메일 발송
  - 응답: `{ success: true, message: "인증 이메일을 확인하세요" }`
- [ ] 검증: 정상 가입 요청 + 도메인 제한 + 중복 이메일

### 7.4 이메일 인증 API

- [ ] `GET /api/auth/verify/:token` — 이메일 인증
  - 처리:
    1. 토큰으로 가입 요청 조회
    2. 만료 확인 (24시간)
    3. 상태 변경: `pending_verification` → `pending_approval`
    4. `verifiedAt` 기록
  - 웹 요청: 인증 결과 페이지 렌더링 (`verify.ejs`)
- [ ] `src/views/verify.ejs` 생성 — 인증 성공/실패 페이지
- [ ] `app.js`에 `GET /verify/:token` 라우트 추가
- [ ] 검증: 유효한 토큰 → 인증 성공, 만료 토큰 → 실패

### 7.5 가입 대기 관리 API (슈퍼유저)

- [ ] `admin-user-controller.js` 또는 별도 컨트롤러에 추가
- [ ] `GET /api/admin/registrations` — 가입 대기 목록
  - `pending_approval` 상태만 반환 (이메일 인증 완료된 것들)
  - 각 항목: 이메일, 가입 메시지, 요청 일시, 인증 일시
- [ ] `POST /api/admin/registrations/:id/approve` — 가입 승인
  - body: `{ groupId }`
  - 처리:
    1. 상태 `pending_approval` 확인
    2. 사용자 계정 생성 (UserStore.create)
    3. 등록 상태 → `approved`
    4. 승인 알림 이메일 발송
  - 응답: `{ success: true, user: { id, email, userKey } }`
- [ ] `POST /api/admin/registrations/:id/reject` — 가입 거절
  - 상태 → `rejected`
  - 거절 알림 이메일 발송
- [ ] `admin-api.js`에 라우트 등록 (슈퍼유저 전용)
- [ ] 검증: 승인 → 계정 생성 + 메일 발송, 거절 → 메일 발송

### 7.6 가입 대기 자동 정리

## 테스트 시나리오

### 정상 케이스

**Given**: allowSignup=true, 이메일 서버 설정됨
**When**: 가입 요청 → 이메일 인증 → 슈퍼유저 승인
**Then**: 계정 생성 완료, 승인 메일 발송, 로그인 가능

### 예외 케이스

**Given**: allowedEmailDomains = ["company.com"]
**When**: user@other.com으로 가입 요청
**Then**: 400 `EMAIL_DOMAIN_NOT_ALLOWED`

**Given**: 이메일 서버 미설정
**When**: 로그인 페이지 접근
**Then**: "가입 요청" 버튼 숨김

### 경계값 테스트

**Given**: 가입 인증 토큰 발급 후 24시간 경과
**When**: 인증 링크 클릭
**Then**: 410 `VERIFICATION_TOKEN_EXPIRED`
