# Phase 6: 내 정보 페이지 + user-key 관리

## 목표

로그인한 사용자가 자신의 계정 정보를 확인하고, 패스워드 변경 및 user-key 재발급을 할 수 있게 한다.

## 선행 조건

- Phase 3 완료 (인증 미들웨어 전환)
- **Phase 4와 병렬 진행 가능** (파일 겹침 없음)

## 아키텍처 참조

- SRS FR-17-010: 내 정보 페이지
- SRS FR-17-006: User-Key 관리

## 구현 체크리스트

### 6.1 내 정보 API

- [ ] `auth-controller.js`에 추가
- [ ] `GET /api/auth/me` — 내 정보 조회
  - 로그인 필수 (세션 기반)
  - 응답:
    ```json
    {
      "success": true,
      "user": {
        "id": "uuid",
        "email": "user@example.com",
        "groupName": "Editor",
        "permissions": ["write", "read"],
        "lastLoginAt": "ISO-8601",
        "userKey": "masked (앞 8자만 표시)"
      }
    }
    ```
  - user-key: 기본 마스킹. 별도 요청 시 전체 표시 (보안 고려)
- [ ] 검증: 로그인 사용자의 정보 조회 성공

### 6.2 user-key 전체 조회

- [ ] `GET /api/auth/me` 에 `?showKey=true` 파라미터 추가
- [ ] **주의**: user-key 원본은 서버에 저장되지 않음 (SHA-256 해시만 저장)
- [ ] 따라서 "보기" 기능은 **재발급 시에만** 원본 제공 가능
- [ ] UI에서는 마스킹된 키만 표시하고, "재발급" 시 새 키 원본 표시
- [ ] 검증: 마스킹 표시 동작

### 6.3 패스워드 변경 API

- [ ] `PUT /api/auth/me/password` 구현
  - 로그인 필수
  - body: `{ currentPassword, newPassword, newPasswordConfirm }`
  - 처리:
    1. `bcrypt.compare(currentPassword, user.passwordHash)` → 실패 시 401
    2. 새 패스워드 강도 검증 (최소 8자)
    3. 새 패스워드 확인 일치
    4. `bcrypt.hash(newPassword, 12)` → `UserStore.updatePassword(userId, hash)`
  - 성공 시 기존 세션 유지 (SRS AC-17-014)
- [ ] 검증: 패스워드 변경 후 기존 세션으로 계속 사용 가능

### 6.4 user-key 재발급 API

- [ ] `POST /api/auth/me/regenerate-key` 구현
  - 로그인 필수
  - 처리:
    1. `UserStore.regenerateUserKey(userId)`
    2. 새 key의 SHA-256 해시 저장, 인덱스 갱신
    3. 기존 key로 인증된 API 요청은 이후 실패
  - 응답: `{ success: true, userKey: "새키원본64자hex" }`
  - **이 응답에서만 원본 키 제공**
- [ ] 검증: 재발급 후 기존 key 무효, 새 key 유효

### 6.5 Admin UI — 내 정보 탭/메뉴

- [ ] `public/js/admin.js`에 내 정보 섹션 추가
  - 모든 권한 사용자에게 표시 (superuser, write, read)
  - 정보 표시: 이메일, 소속 그룹명, 권한, 마지막 로그인
  - **user-key 영역**:
    - 마스킹된 키 표시 (예: `a1b2c3d4...`)
    - "재발급" 버튼 → 확인 다이얼로그 ("기존 키가 즉시 무효화됩니다")
    - 재발급 성공 시 새 키를 복사 가능한 텍스트로 표시
    - "복사" 버튼 (clipboard API)
  - **패스워드 변경 영역**:
    - 현재 패스워드 입력
    - 새 패스워드 입력
    - 새 패스워드 확인
    - "변경" 버튼
- [ ] 검증: 내 정보 조회, 패스워드 변경, user-key 재발급 UI 동작

## 테스트 시나리오

### 정상 케이스

**Given**: Editor 사용자로 /admin 로그인
**When**: 내 정보 탭 → 패스워드 변경 (현재 패스워드 + 새 패스워드)
**Then**: 패스워드 변경 성공, 기존 세션 유지

**Given**: 로그인 상태
**When**: "재발급" 버튼 → 확인
**Then**: 새 user-key 표시, 기존 key로 MCP 호출 시 401

### 예외 케이스

**Given**: 잘못된 현재 패스워드 입력
**When**: 패스워드 변경 시도
**Then**: 401 에러, 변경 실패

**Given**: 새 패스워드가 7자
**When**: 패스워드 변경 시도
**Then**: 400 `WEAK_PASSWORD`

### 경계값 테스트

**Given**: 패스워드 128자 (최대)
**When**: 패스워드 변경
**Then**: 성공
