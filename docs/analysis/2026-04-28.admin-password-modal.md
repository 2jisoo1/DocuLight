# 관리자 ID/PW 변경 모달화 분석

## 현황
- 관리자 페이지의 ID/패스워드 변경 UI는 별도 모달이 아니라 **ManagementModule의 프로필 탭 내부 인라인 폼**으로 렌더링됨
- 페이지 진입 직후 폼이 그대로 노출되어, 비밀번호 입력 필드가 항상 화면에 펼쳐진 상태
- 보안적/UX적으로 명시적 모달 트리거가 필요

## 관련 파일 및 위치
- `views/admin.ejs:37-46` — 관리(Management) 모달 컨테이너
- `public/js/admin.js:1694-1792` — `ManagementModule.loadProfile()`: 프로필 탭 렌더링 (현재 PW 변경 폼이 여기에 inline)
- `public/js/admin.js:1734-1738` — 패스워드 변경 검증
- `public/js/admin.js:2289-2290` — 프로필 버튼 핸들러
- `public/css/admin.css:41-110` — 기본 `.modal` / `.modal-content`
- `public/css/admin.css:1093-1242` — `.mgmt-modal-content` 등 확장 스타일

## 기존 모달 자산 (재사용 가능)
- `.modal` (fixed, 중앙 정렬, z-index 1000)
- `.mgmt-modal-content` 큰 패널 스타일
- 이미 동일 패턴을 쓰는 모달 5종: Rename, Delete, Create, Unsaved Changes, Conflict
- 별도 ModalModule 헬퍼가 있어 open/close 핸들러 재사용 용이
- 신규 CSS 작성은 사실상 불필요

## 수정 제안

### 옵션 A (권장) — 독립 PW 변경 모달
1. `views/admin.ejs`: 새 모달 컨테이너 추가 (`#password-change-modal`)
   - 현재 비밀번호 / 새 비밀번호 / 확인 입력 + 저장·취소 버튼
2. `public/js/admin.js`:
   - `loadProfile()`에서 PW 변경 폼 제거 → "비밀번호 변경" 버튼만 남김
   - 버튼 클릭 시 신규 모달 open
   - 기존 검증/제출 로직(1734-1738 등)을 모달 핸들러로 이전
3. CSS: 기존 `.modal` 클래스 재사용, 추가 스타일 거의 없음

장점: 비밀번호 입력이 명시적 액션으로 격리됨, 화면 노출 최소화, 코드 구조 개선
영향 파일: 3개 (admin.ejs, admin.js, [선택] admin.css)
변경 규모: 약 50–100라인

### 옵션 B — 프로필 탭 내부 서브탭/접힘 영역
- 현재 구조 유지하면서 PW 변경 영역만 collapse/탭으로 숨김
- 변경 규모 작지만 모달화 효과는 부분적

## 영향 범위
- 어드민 프로필 탭 사용자 흐름만 영향. 일반 사용자/뷰어 영향 없음
- 기존 PW 변경 API는 그대로 사용 — 백엔드 변경 불필요
- QA 포인트: 모달 ESC/배경 클릭 닫기, 포커스 트랩, 폼 리셋, 검증 메시지 위치

## 비고
패스워드 8자 검증 버그(별도 분석 문서)와 함께 처리하면 효율적. PW 변경 로직을 모달로 옮기는 김에 `.value.trim()` 적용 권장.
