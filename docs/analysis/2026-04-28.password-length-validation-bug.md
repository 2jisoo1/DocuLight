# 패스워드 길이 검증 버그 분석

## 증상
관리자 페이지에서 패스워드 8자 이상 입력해도 "패스워드는 최소 8자입니다." 에러가 반복적으로 노출됨. 특히 관리자 패스워드 리셋 시 재현.

## 관련 코드 위치 (file:line)

### Frontend
- `public/js/admin.js:1861-1865` — 사용자 추가 폼
  - email은 `.trim()` 적용, password는 미적용 (불일치)
- `public/js/admin.js:1872-1873` — 패스워드 리셋 (버그 핵심)
  ```js
  const pw = prompt('새 패스워드를 입력하세요 (최소 8자):');
  if (!pw || pw.length < 8) { alert('패스워드는 최소 8자입니다.'); return; }
  ```
- `public/js/admin.js:1734-1738` — 패스워드 변경 폼
  ```js
  const nw = document.getElementById('pw-new').value;
  if (nw.length < 8) { msg.textContent = '패스워드는 최소 8자입니다.'; ... }
  ```

### Backend
- `src/controllers/admin/admin-user-controller.js:32, 160, 162` — 검증 자체는 정상
  ```js
  if (!password || password.length < 8) {
    return res.status(400).json({
      error: { code: 'WEAK_PASSWORD', message: 'Password must be at least 8 characters' }
    });
  }
  ```

## 원인 분석 (가설)

### 1. Trim 누락 (가장 유력)
- `prompt()` 반환값과 input value 모두 선행/후행 공백을 그대로 포함
- 사용자가 의도치 않게 공백을 함께 입력하거나 IME 잔존 문자가 끼면 length는 늘어나지만 백엔드에서 trim 후 검증하거나, 다른 검증 단계에서 길이 불일치 발생 가능
- email 필드는 `.trim()`을 적용하면서 password만 빠진 일관성 결여 확인됨

### 2. 일관성 결여
- 사용자 추가, 패스워드 리셋, 패스워드 변경 세 흐름에서 `.trim()` 처리가 모두 다름

### 3. 응답 메시지 표시 로직
- 백엔드 응답의 `error.message`("Password must be at least 8 characters")와 프론트의 한국어 메시지가 별도로 노출되어, 어느 쪽이 트리거됐는지 헷갈릴 수 있음

## 검증 방법
1. 브라우저 DevTools 콘솔에서:
   ```js
   const pw = prompt('패스워드 입력:');
   console.log(pw.length, JSON.stringify(pw));
   console.log(pw.trim().length);
   ```
2. 패스워드 리셋 시 Network 탭에서 요청 body의 `password` 값을 직접 검사 (선/후행 공백 여부)
3. 정확히 8자 비공백 문자만 입력했을 때 에러 발생 여부 재현

## 수정 제안

### 1. `public/js/admin.js:1862` — 사용자 추가
```js
const password = document.getElementById('user-password').value.trim();
```

### 2. `public/js/admin.js:1872-1873` — 패스워드 리셋
```js
const pw = prompt('새 패스워드를 입력하세요 (최소 8자):')?.trim();
if (!pw || pw.length < 8) { alert('패스워드는 최소 8자입니다.'); return; }
```

### 3. `public/js/admin.js:1734` — 패스워드 변경
```js
const nw = document.getElementById('pw-new').value.trim();
```

### 4. Backend 방어 (권장)
`src/controllers/admin/admin-user-controller.js`의 createUser/resetPassword에서 `password.trim().length < 8` 으로 검증.

## 영향 범위
- 패스워드 입력 3개 흐름 (추가/리셋/변경) 전체
- 백엔드 검증은 그대로 두고 프론트만 수정해도 즉시 해결
- 백엔드 trim 추가 시 기존 공백 포함 비밀번호로 가입한 계정의 로그인 영향은 없음 (검증만 trim)
